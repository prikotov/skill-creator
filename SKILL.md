# Skill Creator

SKILL (навык) — переносимый модуль (инструкции + скрипты), позволяющий агенту
автономно выполнять конкретные задачи: работу с API, анализ файлов, другие
специфические действия. Это стандарт структурирования опыта, который агент
загружает по мере необходимости.

Этот скилл — инструкция по созданию навыков. Скрипт `new.php` разворачивает
каркас репо из шаблонов; разделы ниже — как его заполнить и проверить.

## Когда использовать

- Просят сделать скилл из идеи, документа, скрипта или набора команд.
- Просят сделать скилл из выполненной в чате работы: материал — в истории
  сессии (что делали, что не сработало, какие приняли решения).
- Нужно проверить SKILL.md на соответствие правилам ниже (чеклист в конце).
- Нужно оформить репо скилла для публикации (README, LICENSE, CI, защита ветки).

## Запуск

Пути — от каталога с SKILL.md.

```bash
# Скилл-инструкция без скриптов: только SKILL.md, README, тесты структуры
php scripts/new.php --name prompt-review

# Скилл с двумя скриптами: по шагу на скрипт, общий клиент, CI
php scripts/new.php --name moex-site-core --script map --script search

# Явный каталог, заголовок, описание для модели
php scripts/new.php --name cbr-core --dir /home/dp/MyProjects/cbr-core \
  --title "CBR Core" --description "Сайт и API ЦБ: карта, поиск, ОРФР" --script orfr
```

### Опции new.php

| Опция | Описание | Значения | По умолчанию |
|-------|----------|----------|--------------|
| `--name` | Имя скилла (обязательно) | kebab-case | — |
| `--dir` | Каталог репо | путь | `~/MyProjects/<name>` |
| `--title` | Заголовок `# …` | строка | Name Case из name |
| `--description` | Описание скилла для модели (frontmatter) | строка | заглушка |
| `--license` | Лицензия: `MIT` (файл LICENSE) или `none` | `MIT`, `none` | `MIT` |

## Результат

stdout — JSON; ошибки — в stderr. Код выхода 0/1.

| Поле | Что значит |
|------|------------|
| `ok` | Каркас создан |
| `dir` | Каталог репо |
| `files[]` | Созданные файлы |
| `placeholders_left` | Плейсхолдеры `{{…}}` по файлам — **агент дорабатывает их сам** по правилам этого скилла до запуска `tests/run.php` в каркасе |
| `next[]` | Что делать дальше по шагам |

## Структура скилла

```
skill-name/
├── SKILL.md          # Обязательный
├── scripts/          # Опционально: скрипты
├── references/       # Опционально: справка, механика
└── assets/           # Опционально: шаблоны, данные
```

В SKILL.md — только то, что нужно агенту в каждый запуск. Подробности
уходят в отдельные файлы: скрипты — в `scripts/`, справка и механика — в
`references/`, шаблоны и данные — в `assets/`. Агент откроет их, когда задача
потребует, и не будет тратить контекст на лишнее.

## SKILL.md

### YAML Frontmatter (обязательно)

```yaml
---
name: skill-name
description: Что делает skill (кратко).
license: MIT
---
```

Требования:

- `name`: kebab-case, только строчные, без пробелов.
- `description`: что делает skill и когда применять; до 1024 символов.
  Агент выбирает скилл по description — пишите в него ситуации применения.
- Без XML-тегов (`< >`).

### Тело SKILL.md

| Раздел | Описание |
|--------|----------|
| **Когда использовать** | Ситуации, контекст применения |
| **Как использовать** | Шаги с командами, опциями, примерами |
| **Результат** | Что и где получим |
| **Правила агента** | Запреты и границы: что нельзя, что делать в спорных случаях |

Четвёртый раздел добавлен к исходной структуре практикой: без него агент
угадывает (пример: «сниппеты поисковика — только для выбора URL»).

### Шаг

Один скрипт — один шаг; скилл без скриптов — только разделы-инструкции.
Шаг содержит:

1. **Инструкция** — что нужно сделать агенту.
2. **Команда** — синтаксис вызова.
3. **Опции** — таблица (опция / описание / значения / по умолчанию).
4. **Результат шага** — что получим (для скриптов: таблица полей stdout).
5. **Примеры** — конкретные вызовы, с комментариями что делают.

````text
**Шаг 1:** Название
    command [опции]

Опции:

| Опция | Описание | Значения | По умолчанию |
|-------|----------|----------|--------------|
| --sort | Поле сортировки | visits, date | visits |

Примеры:

    # Топ-10
    command --limit 10
````

### Что не в SKILL.md

- Устройство клиента, порядок способов, требования к бинарнику, ключи —
  в README и `references/`.
- Сетевые пробы, тестовые запросы, кейсы владельца — не пишутся; в
  `references/` только переиспользуемые факты с датами.
- Дублей между SKILL.md, README и AGENTS.md нет: каждый факт в одном файле
  (таблица «SKILL.md или README?» — `references/rules.md`).

## README.md

- Первый абзац говорит прямо: это **skill для AI-агентов**, как подключается,
  кто читает SKILL.md, а кто README.
- Разделы: Зачем → Что вы получите (таблица файлов) → Зависимости → Установка
  → Использование (по скрипту: примеры, параметры, результаты) → Через агента
  (реальный запрос из истории) → Конфиг и секреты → Как устроено → Правила
  → Лицензия.


## Скрипты

- stdout — JSON-контракт (не ломать без причины), прогресс и предупреждения —
  в stderr, код выхода 0/1.
- PHP 8.4+, ext-curl, без composer (стек владельца). Клиент — в корне репо,
  скрипты — в `scripts/`.
- Транзакции при массовой записи, индексы под реальные запросы (PDO
  автокоммитит на строку — импорт деградирует до минут).
- Секреты — только свой конфиг-дотфайл (в `.gitignore`, права 600) или
  рантайм-env; env-файлы проектов не читать.


## Публикация

- Репо на GitHub: description начинается со «Skill для AI-агентов: …»,
  topics (`skill`, `skill-md`, `ai-agents`, `php`…), LICENSE MIT, CI
  (`php -l` + офлайн-тесты), branch protection `main` (PR обязателен).
- AGENTS.md в репо — для агентов, разрабатывающих сам скилл: адресаты
  документации, архитектура, контракты вывода, правила разработки.

## Скилл из истории сессии

- Материал — сама переписка: какие команды выполнялись, какие сайты/способы
  не сработали и почему, какие решения принял пользователь и на чём основал.
- Извлечь из истории: реальные команды (они станут примерами), реальные
  запросы пользователя (дословно — в README, «Через агента»), отрицательные
  результаты с датой (в `references/`), решения пользователя (в правила).
- Формулировки пользователя — первичны: если он переименовал термин или
  запретил слово, в скилл идёт его вариант, а не литературный.
- Историю читать, не вспоминать: лог сессии в `~/.pi/agent/sessions/`
  (jsonl, роль `user`), искать по ключевым словам темы.
- Перед каркасом подтвердить у пользователя объём: что из сделанного входит
  в скилл, что осталось побочным.

## Чеклист

Перед публикацией или при ревизии:

- [ ] Папка в kebab-case
- [ ] Файл `SKILL.md` (регистр важен)
- [ ] YAML frontmatter обрамлён `---`
- [ ] `name`: kebab-case
- [ ] `description` краткий: что делает и когда применять
- [ ] Раздел «Когда использовать»
- [ ] Раздел «Как использовать» с опциями и примерами
- [ ] Раздел «Результат» с описанием
- [ ] Раздел «Правила агента»
- [ ] Ни одного упоминания устройства клиента, порядка способов, ключей
      в SKILL.md — это README / `references/`
- [ ] README говорит «skill для AI-агентов» в первом абзаце; пример запроса
      агенту — реальный, из истории
- [ ] stdout — JSON, stderr — прогресс; `php -l` и `php tests/run.php` зелёные
- [ ] Секретов в коде и доке нет; конфиг в `.gitignore`

## Правила языка

- Один термин — одно слово («физлица», «способ доступа»); синонимы не плодить.
- Короткие предложения, активный залог, один тезис — одно предложение.
- Термины и аббревиатуры раскрывать при первом упоминании.
- Формулировки без лозунгов и дублей; запретные слова проекта — в его AGENTS.md.
