# Skill Creator

SKILL (SKILL.md, навык) — переносимый модуль (инструкции + скрипты), позволяющий агенту
автономно выполнять конкретные задачи: работу с API, анализ файлов, другие
специфические действия. Это стандарт структурирования опыта, который агент сам может
загружать по мере необходимости.

Этот скилл — инструкция по созданию скилов. Скрипт скила `create.php` разворачивает
каркас репо из шаблонов; разделы ниже — как его заполнить и проверить.

## Когда использовать

- Просят сделать скилл.
- Нужно проверить скилл на соответствие правилам.
- Нужно оформить репо скилла для публикации.

## Запуск

> Все пути от каталога со SKILL.md.

```bash
# Скилл-инструкция без скриптов: только SKILL.md, README, тесты структуры
php scripts/create.php --name prompt-review --dir /path/to/prompt-review

# Явный каталог, заголовок, описание для модели
php scripts/create.php --name cbr-core --dir /path/to/cbr-core \
  --title "CBR Core" --description "Сайт и API ЦБ: карта, поиск, ОРФР"
```

### Опции create.php

| Опция | Описание | Значения | По умолчанию |
|-------|----------|----------|--------------|
| `--name` | Имя скилла (обязательно) | kebab-case | — |
| `--dir` | Каталог репо (обязательно) | абсолютный путь | — |
| `--title` | Заголовок `# …` | строка | Name Case из name |
| `--description` | Описание скилла для модели (frontmatter) | строка | заглушка |
| `--license` | Лицензия | `MIT`, `none` | `MIT` |

## Результат

stdout — JSON; ошибки — в stderr. Код выхода 0/1.

| Поле | Что значит |
|------|------------|
| `ok` | Каркас создан |
| `files[]` | Созданные файлы |

## Структура скилла

```
skill-name/
├── SKILL.md          # Обязательный
├── scripts/          # Опционально: скрипты
├── references/       # Опционально: справка, механика
└── assets/           # Опционально: шаблоны, данные
```

В SKILL.md — только то, что нужно агенту в каждый запуск. Подробности
уходят в отдельные файлы: скрипты — в `scripts/`, справка и механика — в
`references/`, шаблоны и данные — в `assets/`. Агент откроет их, когда задача
потребует, и не будет тратить контекст на лишнее.

## SKILL.md

### YAML Frontmatter (обязательно)

```yaml
---
name: skill-name
description: Что делает skill и когда применять (кратко).
license: MIT
---
```

Требования:

- `name`: kebab-case, только строчные, без пробелов.
- `description`: что делает skill и когда применять; до 1024 символов.
  Агент выбирает скилл по description — пишите в него ситуации применения.
- Без XML-тегов (`< >`).

### Тело SKILL.md

| Раздел | Описание |
|--------|----------|
| **Когда использовать** | Ситуации, контекст применения |
| **Как использовать** | Шаги с командами, опциями, примерами |
| **Результат** | Что и где получим |
| **Правила агента** | Запреты и границы: что нельзя, что делать в спорных случаях |

### Как использовать

Раздел описывает алгоритм действий агента, разбитый на шаги. Шаг это инструкция для агента: вызвать скрипт,
прочитать файл, спросить пользователя, проверить результат. Использование скрипта не обязательно, но рекомендуется, это один из детерменированных инструментов который облегчает работу агенту.

Шаг содержит:

1. **Инструкция** — что нужно сделать агенту. Обязательна.
2. **Команда** — если шаг вызывает скрипт: синтаксис вызова.
3. **Опции** — если у команды есть опции: таблица (опция / описание /
   значения / по умолчанию).
4. **Результат шага** — что получим и где: файл, поля stdout, решение.
5. **Примеры** — если есть команда: конкретные вызовы с комментариями.

````text
**Шаг 1:** Загрузить данные за период
    php scripts/report.php [дата_от] [дата_до]

Опции:

| Опция | Описание | Значения | По умолчанию |
|-------|----------|----------|--------------|
| {добавь пример обязательной опции} | {добавь пример обязательного описания(обязательно)} | {добавь пример} | — |
| --sort | Поле сортировки | visits, date | visits |
 

Примеры:

    # Топ-10
    php scripts/report.php --limit 10

**Шаг 2:** Проверить, что данных достаточно

Если строк меньше 30 — сообщить пользователю и остановиться, не делать выводов.

**Шаг 3:** Оформить результат

Свести таблицу в заметку; цифры — с датой и источником.
````

### Где какой факт

Каждый факт живёт в одном файле:

| Вопрос | Файл |
|--------|------|
| Когда применять, как действовать, что получится | SKILL.md |
| Какие боли решает, как установить, из чего состоит, как настроить | README.md |
| Как вести разработку скилла агентом: контракты вывода, тесты | AGENTS.md |
| Как устроен API или сайт, какие ловушки | `references/` |

## README.md

- Первый абзац говорит прямо: это **skill для AI-агентов**, как подключается.
- Содержит разделы: Зачем → Что вы получите → Зависимости → Установка → Использование
  → Конфиг и секреты → Как устроено → Правила → Лицензия.
- «Что вы получите» — что сможет агент после установки.
- «Использование» — примеры запросов и что агент по ним сделает.

# AGENTS.md

В репо — для агентов, разрабатывающих сам скилл: адресаты документации, архитектура, контракты вывода, правила разработки.


## Скрипты

- В stdout — JSON-контракт, прогресс и предупреждения
- В stderr — код выхода 0/1.
- Использовать PHP 8.4+, ext-curl, без composer. Общий код — в `shared/`, скрипты — в `scripts/`.
- Секреты хранить в своём конфиг-файле.
- Конфиг это дотфайл в корне проекта где используется скилл: `.<skillname>.config.json`, пример: `web-research-fallback` → `.web-research-fallback.config.json`. Файл конфигурации в `.gitignore`, права на него 600.
- Пример конфигурации размещать в корне скила как `.<skillname>.config.example.json`

## Публикация

Репо на GitHub:

- description начинается со «Скилл для ИИ-агентов: ...»,
- topics (`skill`, `skill-md`, `ai-agents`, `php`, ...)
  (`php -l` + офлайн-тесты), branch protection `main` (PR обязателен).

## Как создавать скилл из истории сессии

- Материал — сама переписка: какие команды выполнялись, какие сайты/способы
  не сработали и почему, какие решения принял пользователь и на чём основал.
- Извлечь из истории: реальные команды (они станут примерами), реальные
  запросы пользователя (дословно — в README, «Использование»), отрицательные
  результаты с датой (в `references/`), решения пользователя (в правила).
- Формулировки пользователя — первичны: если он переименовал термин или
  запретил слово, в скилл идёт его вариант.
- Историю брать из лога сессии, для pi: `~/.pi/agent/sessions/`
  (jsonl, роль `user`), искать по ключевым словам темы.
- Перед каркасом подтвердить у пользователя объём: что из сделанного входит
  в скилл, что осталось побочным.

## Чеклист

Перед публикацией или при ревизии:

- [ ] Папка в kebab-case
- [ ] Файл `SKILL.md` (регистр важен)
- [ ] YAML frontmatter обрамлён `---`
- [ ] `name`: kebab-case
- [ ] `description` краткий: что делает и когда применять
- [ ] Раздел «Когда использовать»
- [ ] Раздел «Как использовать» с опциями и примерами
- [ ] Раздел «Результат» с описанием
- [ ] Раздел «Правила агента»
- [ ] Устройство, настройки и механика — в README / `references/`,
      в SKILL.md — когда применять и как действовать
- [ ] README говорит «Скилл для AI-агентов» в первом абзаце; пример запроса
      агенту — реальный, из истории
- [ ] stdout — JSON, stderr — прогресс; `php -l` и `php tests/run.php` зелёные
- [ ] Секретов в коде и доке нет; конфиг в `.gitignore`
- [ ] Личных путей (`/home/<user>/…`) в коде и доке нет; в примерах — `/path/to/…`

## Правила языка

- Один термин — одно слово; синонимы не плодить.
- Короткие предложения, активный залог, один тезис — одно предложение.
- Термины и аббревиатуры раскрывать при первом упоминании.
- Формулировки без лозунгов и дублей.
