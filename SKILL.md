# Skill Creator

Навык — закреплённая методика: последовательность действий, правила
решений и критерии качества. Знания и умения у модели есть: параметры, контекст,
рассуждение, инструменты. Навык определяет, как применить их к классу задач.

Навык — часть триады «знание — умение — навык». Подробнее в `references/create.md`.

SKILL.md — форма навыка: переносимый модуль (инструкции и скрипты),
позволяющий агенту автономно выполнять конкретные задачи: работу через API, анализ
данных, другие специфические действия. Это стандарт структурирования опыта,
который агент сам может загружать по мере необходимости.

Этот навык — инструкция по жизненному циклу навыка: создание, использование,
улучшение — и снова использование.

## Когда использовать

- Просят сделать или опубликовать навык — раздел «# Создание».
- Просят проверить, оценить навык или собрать опыт его использования —
  раздел «# Использование» («## Проверка в работе»).
- Просят улучшить навык — раздел «# Улучшение».

Неоднозначно — спроси пользователя.

## Создание

Основа — методика создания навыка: `references/create.md`.

Навык можно создать из истории сессии. Попробуй сначала вручную сделать с пользователем работу, которую навык будет автоматизировать. Добейся результата. Затем:

- Возьми материалом переписку: какие команды выполнялись, какие сайты/способы
  не сработали и почему, какие решения принял пользователь и на чём основал.
- Извлеки из истории реальные команды (они станут скриптами и примерами), реальные
  запросы пользователя, отрицательные результаты (в ограничения), решения пользователя (в правила).
- Найди историю в логе сессии, для pi: `~/.pi/agent/sessions/`.
- Подтверди у пользователя объём до каркаса: что из сделанного входит
  в навык, что нет.

### Каркас: create.php

Каркас навыка в файловой системе разворачивает скрипт:

```bash
# Навык без скриптов: только SKILL.md, README, тесты структуры
php <skill-dir>/scripts/create.php --name prompt-review --dir /path/to/prompt-review

# Явный каталог, заголовок, описание для модели
php <skill-dir>/scripts/create.php --name cbr-core --dir /path/to/cbr-core \
  --title "CBR Core" --description "Сайт и API ЦБ: карта, поиск, ОРФР"
```

`<skill-dir>` — каталог этого SKILL.md, подставь его в команду.

Опции:

| Опция           | Описание                                 | Значения               | По умолчанию      |
| --------------- | ---------------------------------------- | ---------------------- | ----------------- |
| `--name`        | Имя навыка (обязательно)                 | kebab-case             | —                 |
| `--dir`         | Каталог навыка (обязательно)             | абсолютный путь        | —                 |
| `--title`       | Заголовок `# …`                          | строка                 | Name Case из name |
| `--description` | Описание навыка для модели (frontmatter) | строка                 | заглушка          |
| `--license`     | Лицензия   | `MIT`, `none`, [SPDX-ID](https://spdx.org/licenses/) | `MIT`             |

Результат — stdout JSON; ошибки — в stderr. Код выхода 0/1.

| Поле                | Что значит                                               |
| ------------------- | -------------------------------------------------------- |
| `ok`                | Каркас создан                                            |
| `files[]`           | Созданные файлы                                          |
| `placeholders_left` | Какие заглушки `{{…}}` в каких файлах осталось заполнить |

### Тестирование

Тестируй навык отдельной сессией агента: свежая сессия видит только SKILL.md
и его файлы — она проверяет самодостаточность навыка. Это тестирование
на гипотетических задачах; разбор реального использования в разделе «### Проверка в работе».

- запиши задачи и критерии успеха до выполнения: типовая, пограничная и задача,
  где навык неуместен (категории — `references/evaluate.md`);
- поставь навык штатно в текущем проекте — `.agents/skills/<name>`, работу
  веди в нём. Сессия свежая: чистый контекст, без истории разработки;
- запусти одноразовую сессию в каталоге проекта, на примере pi:

```bash
pi -a -p "<промпт задачи>"
```

  `-p` — одноразовый запуск: агент выполнит задачу с чистым контекстом,
  выведет итоговый ответ и завершится. `-a` — доверие ресурсам проекта:
  в недоверенном каталоге скиллы не загрузятся и тест пойдёт мимо методики.
  Полный трек событий — `pi --mode json "<промпт>" > run.jsonl`.

- сверь результаты с критериями; вноси правки и повторяй тестирование,
  пока критерии не выполнены.

### Публикация

Публикация навыка: репозиторий на GitHub, затем заполнение `package` —
`references/publish.md`.

## Использование

### Отчёты о работе

Отчёт пишет агент по прямой просьбе пользователя или по триггеру: один разбор — один файл. Формат,
шапка и шаги создания описаны в `references/reports.md`. Сами отчеты хранятся в `_reports/<name>/` проекта,
где навык работал.

### Проверка в работе

Проверка разбирает историю сессий и показывает, как навык работал на реальных
задачах. Методики: разбор — `references/audit.md`, оценка —
`references/evaluate.md`, категории наблюдений — `references/harvest.md`.

Итог проверки — отчёт (`references/reports.md`); его наблюдения — вход для
«Улучшение».

Проверка запускается по прямой просьбе пользователя. Второй триггер (важно) —
недовольство работой навыка: жалоба, раздражение, резкие формулировки, мат.

## Улучшение

Когда улучшать: прямо просят улучшить навык или проверка в работе
выявила проблемы.

Полная методика — `references/evolve.md`.

1. Собери наблюдения. Есть история использования — разбор по
   `references/audit.md`; готовые отчёты в `_reports/<name>/` — тоже вход.
   Похожие решения чужих авторов — реестр `references/similar-solutions.md`.
   Нет истории — улучшай по обратной связи пользователя.
2. Внеси правки: глобальный навык — через PR в его репозиторий, локальный —
   на месте.
3. Заверши серию правок тестированием на том же наборе задач («Тестирование»).
4. Оформи улучшение — `references/package.md`.

## Форма навыка

Форма одна: при создании она шаблон, при правке — рамка.

### Структура навыка

```
skill-name/
├── SKILL.md          # Обязательный
├── README.md         # Для агентов и человека: что это, как установить и настроить
├── AGENTS.md         # Для агентов-разработчиков навыка
├── CHANGELOG.md      # История улучшений: проблема → решение → PR
├── tests/            # Тесты: php tests/run.php
├── scripts/          # Опционально: скрипты
├── references/       # Опционально: справка, механика
└── assets/           # Опционально: шаблоны, данные
```

В SKILL.md — только то, что нужно агенту при каждом запуске. Подробности
уходят в отдельные файлы:

- в `scripts/*` — скрипты,
- в `references/*.md` — справка и механика,
- в `assets/` — шаблоны и данные.

Агент откроет их, когда задача потребует, и не будет тратить контекст на лишнее.

### Зоны ответственности файлов

Каждое правило живёт в одном файле:

| Файл              | Вопрос                                                                |
| ----------------- | --------------------------------------------------------------------- |
| SKILL.md          | Когда применять, как действовать, что получится                       |
| README.md         | Какие боли решает, как установить, из чего состоит, как настроить     |
| AGENTS.md         | Как вести разработку навыка агентом: контракты вывода, тесты          |
| CHANGELOG.md      | История улучшений: проблема → решение → PR                            |
| `references/*.md` | Методики и конвенции — что читать сверх SKILL.md |
| Сессии | Тестовые запросы и пробы владельца: агент пишет их в сессию,
  не в документацию; достать — `references/audit.md` |

### SKILL.md

#### YAML Frontmatter (обязательно)

```yaml
---
name: skill-name
description: Что делает навык и когда применять (кратко).
license: MIT
depends_on:
  - other-skill
package: https://github.com/owner/skill-name
version: 0.1.0
updated: 2026-11-27 14:30 UTC
hash: <sha256>
---
```

Требования:

- `name`: имя навыка; kebab-case, только строчные, без пробелов, до 64 символов.
- `description`: описание навыка, что делает и когда применять; до 1024 символов.
  Агент выбирает навык по description — пиши в него ситуации применения.
- `depends_on`: зависимости навыка; необязательный список имён навыков, нужных для работы.
  Подробно — `references/depends-on.md`.
- `package`: URL репозитория-источника. Есть — навык глобальный, улучшения
  через PR; нет — навык локальный, улучшают на месте.
- `version`: версия навыка; внешняя (тег источника) либо локальная.
- `updated`: дата и время последней правки, `YYYY-MM-DD HH:MM UTC`.
- `hash`: отпечаток содержимого копии; пересчёт — `scripts/hash.php --write`.

#### Тело SKILL.md

Тело генерирует скрипт `create.php` из шаблона `assets/SKILL.template.md` — там полная
структура: разделы, шаг со скриптом, опции, примеры, результат, правила.

Держи тело до 500 строк. Краткость сестра таланта.

Тело состоит из разделов:

| Раздел                 | Описание                                                        |
| ---------------------- | --------------------------------------------------------------- |
| **Когда использовать** | Ситуации, контекст применения                                   |
| **Как использовать**   | Шаги с командами, опциями, примерами                            |
| **Результат**          | Конечный результат навыка: что получим, где и в каком формате   |
| **Правила для агента** | Запреты и границы: что нельзя, что делать в неописанных случаях |

#### Раздел «Как использовать»

Раздел описывает алгоритм действий агента, разбитый на шаги. Шаг — это инструкция для агента: вызвать скрипт,
прочитать файл, спросить пользователя, проверить результат. Использование скрипта не обязательно, но рекомендуется.
Скрипт — это детерминированный инструмент, который облегчает работу агенту.

Шаг содержит:

1. **Инструкция** — что нужно сделать агенту. Обязательна.
2. **Команда** — если шаг вызывает скрипт: синтаксис вызова.
3. **Опции** — если у команды есть опции: таблица (опция / описание / значения / по умолчанию).
4. **Результат шага** — промежуточный результат: что получим, где и в каком формате. Обычно это файл, его пишет скрипт. Если результат простой, достаточно вывода текста в stdout.
5. **Примеры** — если есть команда: конкретные вызовы с комментариями.

#### Команды скриптов

- Форма команды — плейсхолдер каталога навыка: `<skill-dir>/scripts/main.php`.
  `<skill-dir>` — каталог этого SKILL.md. Агент подставляет абсолютный путь
  при запуске; плейсхолдер не копируется дословно.
- Запрещены абсолютные пути и пути от корня проекта.
- Перед блоком кода — одна строка: «`<skill-dir>` — каталог этого SKILL.md,
  подставь его в команду». Пояснение-комментарий внутри блока недостаточно:
  агент копирует команду, а не комментарий.
- Упоминания файлов в тексте — относительные: `scripts/main.php`.
- Скрипт сам определяет свой каталог и не зависит от каталога запуска.

### README.md

- Первый абзац говорит, что это за навык и какую проблему решает.
- Содержит разделы:
  - Зачем — какие боли решает и кому нужен.
  - Что вы получите — что сможет агент после установки навыка.
  - Зависимости — что нужно для работы: среда, программы, другие навыки.
  - Установка — как подключить навык: клон или симлинк в каталог skills.
  - Использование — примеры запросов и что агент по ним сделает.
  - Конфиг и секреты — какой конфиг нужен навыку и где хранятся секреты.
  - Как устроено — из чего состоит: скрипты, файлы, схема работы.
  - Правила — ограничения использования: что навык делает и чего не делает.
  - Лицензия — под какой лицензией распространяется навык.

### AGENTS.md

Для агентов, разрабатывающих навык.

Содержит разделы:

- Что это за проект — что это за навык и адресаты документации.
- Архитектура — из чего состоит: файлы, скрипты, контракты вывода.
- Правила разработки — как вести репозиторий: тесты, CI, коммиты.

### Скрипты

- Результат — JSON в stdout; набор полей описан в разделе «Результат», его парсят агент и тесты.
- В stderr — прогресс, предупреждения и ошибки; код выхода 0/1.
- Каждый скрипт покрыт тестом вызова, зеркальным по пути: `scripts/hash.php` →
  `tests/scripts/hash.php`. Файл регистрируется в `tests/run.php`; fixture-вход →
  ожидаемый код выхода и формат вывода.
- PHP 8.4+; composer — только когда без него не решить. Общий код — в `shared/`, скрипты — в `scripts/`.

### Конфигурация

- Секреты хранить в своём конфиг-файле.
- Конфиг — это дотфайл в корне проекта, где используется навык: `.<skillname>.config.json`, пример: `web-research-fallback` → `.web-research-fallback.config.json`. Файл конфигурации в `.gitignore`, права на него 600.
- Пример конфигурации размещать в корне навыка как `.<skillname>.config.example.json`

## Правила для агента

- Начинай создание навыка с методики: класс задач, результат, последовательность
  действий, правила решений, критерии качества. Источник методики — пользователь,
  документация или история сессии.
- Разворачивай каркас скриптом `create.php` — он фиксирует методику в файлах
  по шаблону. Скрипт только создаёт файлы. `git init`, коммит и публикация —
  отдельные действия.
- После каркаса не закрывай работу: прогони «Тестирование» и правки до
  выполнения критериев — улучшение входит в создание.
- Пиши словами пользователя. Если он переименовал термин или запретил слово,
  в навык идёт вариант пользователя.
- Правило или инструкцию пиши один раз и только в один файл. В какой — смотри
  в таблице «Зоны ответственности файлов».
- Держи секреты (токены, ключи, пароли) в отдельном конфиг-файле.
- В примерах вместо настоящих путей пиши `/path/to/…`.

## Чеклист

Перед публикацией, при проверке или улучшении сверяй форму навыка по чеклисту.
Полная оценка по практике — `references/evaluate.md`:

- [ ] Папка в kebab-case
- [ ] Файл `SKILL.md` (регистр важен)
- [ ] YAML frontmatter обрамлён `---`
- [ ] `name`: kebab-case, до 64 символов
- [ ] `description`: что делает и когда применять, до 1024 символов
- [ ] Раздел «Когда использовать»
- [ ] Раздел «Как использовать» с опциями и примерами
- [ ] Раздел «Результат» с описанием
- [ ] Раздел «Правила для агента» с описанием действий при выходе за границы навыка
- [ ] Тело SKILL.md до 500 строк
- [ ] Устройство, настройки и механика — в README / `references/`,
      в SKILL.md — когда применять и как действовать
- [ ] README говорит, какую боль решает
- [ ] stdout — результат, stderr — прогресс и ошибки, код выхода 0/1
- [ ] Команды скриптов — в форме `<skill-dir>/scripts/…`, без абсолютных путей и путей от корня проекта
- [ ] Скрипт не зависит от каталога запуска
- [ ] Тесты зеркальны исходникам: scripts/x.php → tests/scripts/x.php
- [ ] `php -l` и `php tests/run.php` зелёные
- [ ] Улучшения в CHANGELOG.md; `version`, `updated`, `hash` совпадают с верхней записью
- [ ] Секретов в коде и доке нет; файл конфига в `.gitignore`
- [ ] Личных путей в коде и доке нет; в примерах — `/path/to/…`

## Правила языка

- Одно понятие — один термин; синонимы запрещены.
- Используй точные профессиональные термины из предметной области.
- Формулировки однозначные, без двойного толкования и оценочных слов.
- Пиши короткими предложениями без пропуска объектов действия.
- Используй активный залог по схеме: «одно действие (или тезис) — одно предложение».
- Расшифровывай узкие термины и аббревиатуры при первом упоминании.
- Убирай вводную «воду», общие призывы и повторы.

## Источники

Методики, на которых построены разделы:

- `references/create.md` — методика создания навыка.
- `references/evaluate.md` — методика оценки: категории задач, критерии.
- `references/harvest.md` — сбор опыта из истории сессий: категории наблюдений, статусы.
- `references/evolve.md` — методика улучшения.
- `references/audit.md` — разбор истории сессий: поиск, хронология, правила.
- `references/package.md` — источник, версия, hash, оформление улучшения.
- `references/publish.md` — публикация репозитория.
- `references/reports.md` — конвенция отчётов о работе.
- `references/depends-on.md` — зависимость навыка от другого навыка.
