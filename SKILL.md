# Skill Creator

Создание и проверка скиллов. Скрипт `new.php` разворачивает каркас репо
из шаблонов; правила ниже — как заполнить каркас.

## Когда использовать

- Просят сделать скилл из идеи, документа, скрипта или набора команд.
- Нужно проверить SKILL.md на соответствие правилам.
- Нужно оформить репо скилла для публикации (README, LICENSE, CI, защита ветки).
- Переводят скилл с Python на PHP — каркас уже PHP.

## Запуск

Из корня репо скилла; после установки в проект путь будет
`.agents/skills/skill-creator/scripts/`.

```bash
# Новый скилл в ~/MyProjects/<name>
php scripts/new.php --name moex-site-core --what "карта сайта Мосбиржи и поиск"

# С явным каталогом, заголовком и описанием для модели
php scripts/new.php --name cbr-core --dir /home/dp/MyProjects/cbr-core \
  --title "CBR Core" --description "API и сайт ЦБ: карта, поиск, ОРФР" \
  --what "доступ к данным ЦБ" --script orfr
```

### Опции new.php

| Опция | Описание | Значения | По умолчанию |
|-------|----------|----------|--------------|
| `--name` | Имя скилла (обязательно) | kebab-case | — |
| `--dir` | Каталог репо | путь | `~/MyProjects/<name>` |
| `--title` | Заголовок `# …` | строка | Name Case из name |
| `--description` | Описание для модели: когда использовать | строка | заглушка |
| `--what` | Чем занимается скрипт (для фраз) | строка | «что делает скрипт» |
| `--script` | Имя основного скрипта в `scripts/` | kebab-case | `main` |
| `--owner` | Владелец GitHub (URL в README) | логин | `prikotov` |

## Результат

stdout — JSON; ошибки — в stderr. Код выхода 0/1.

| Поле | Что значит |
|------|------------|
| `ok` | Каркас создан |
| `dir` | Каталог репо |
| `files[]` | Созданные файлы |
| `placeholders_left` | Плейсхолдеры `{{…}}` по файлам — их заполнить руками |
| `next[]` | Что делать дальше по шагам |

## Правила агента

Структура и разделы — из SKILL-CREATION.md. Ниже — что писать в каждый
раздел и что в SKILL.md не писать (накоплено на наших скиллах).

### SKILL.md

- **Frontmatter**: `name` kebab-case, `description` — что делает skill,
  до 1024 символов, без XML-тегов. Пишите в description ситуации применения:
  агент выбирает скилл по нему.
- **Структура**: **Когда использовать → Как использовать → Результат →
  Правила агента**.
- **Когда использовать** — список ситуаций, контекст применения.
- **Как использовать** — по шагам: инструкция, команда, таблица опций
  (опция / описание / значения / по умолчанию), примеры. Один скрипт —
  один шаг.
- **Результат** — что и где получим; для скриптов — таблица полей stdout.
- **Правила агента** — запреты и границы: что агенту нельзя, что делать в
  спорных случаях. Это четвёртый обязательный раздел; его нет в исходной
  инструкции, но без него агент угадывает.
- Механика API, устройство клиента, порядок способов и ключи — в `references/`
  и README, не в SKILL.md. SKILL.md — навык; README — устройство.

### README.md — для человека

- Первый абзац говорит прямо: это **skill для AI-агентов**, как подключается,
  кто читает SKILL.md, а кто README.
- Разделы: Зачем → Что вы получите (таблица файлов) → Зависимости → Установка
  → Использование (по скрипту: примеры, параметры, результаты) → Через агента
  (реальный запрос из истории, не выдуманный) → Конфиг и секреты → Как
  устроено → Правила → Лицензия.
- Пример запроса агенту — из реальной истории сессии, дословно.

### Что НЕ в SKILL.md и НЕ в README

- Сетевых проб, тестовых запросов и кейсов владельца — в `references/` пишут
  только переиспользуемое: поведение важных сайтов, движков, способы.
- Отрицательные результаты фиксировать с датой: «проверено YYYY-MM-DD — не
  пригоден, причина».
- Дублей между SKILL.md, README и AGENTS.md: каждый факт живёт в одном файле
  (таблица «SKILL.md или README?» — `references/rules.md`).

### Скрипты

- stdout — JSON-контракт (не ломать без причины), прогресс и предупреждения —
  в stderr, код выхода 0/1.
- PHP 8.4+, ext-curl, без composer (стек владельца). Клиент — в корне репо,
  скрипты — в `scripts/`.
- Транзакции при массовой записи, индексы под реальные запросы (PDO
  автокоммитит на строку — импорт деградирует до минут).
- Секреты — только свой конфиг-дотфайл (в `.gitignore`, права 600) или
  рантайм-env; env-файлы проектов не читать.

### Публикация

- Репо на GitHub: description начинается со «Skill для AI-агентов: …»,
  topics (`skill`, `skill-md`, `ai-agents`, `php`…), LICENSE MIT, CI
  (`php -l` + офлайн-тесты), branch protection `main` (PR обязателен).
- AGENTS.md в репо — для агентов, разрабатывающих сам скилл: адресаты
  документации, архитектура, контракты вывода, правила разработки.

## Чеклист проверки скилла

Пройдите по списку перед публикацией или при ревизии:

- [ ] Frontmatter: `name` kebab-case, `description` = «когда использовать»,
      без XML-тегов, `license: MIT`.
- [ ] Разделы: Когда использовать → Запуск → Результат → Правила агента.
- [ ] У каждого скрипта: таблица опций (4 колонки), комментированные примеры,
      таблица полей результата, код выхода.
- [ ] Ни одного упоминания устройства клиента/порядка способов/ключей в
      SKILL.md — это README/`references/`.
- [ ] README говорит «skill для AI-агентов» в первом абзаце; пример запроса
      агенту — реальный, из истории.
- [ ] `references/` содержит только переиспользуемые факты с датами.
- [ ] stdout — JSON, stderr — прогресс; `php -l` и `php tests/run.php` зелёные.
- [ ] Секретов в коде и доке нет; конфиг в `.gitignore`.
- [ ] Реально протестирован на задаче пользователя, не только на моках.

## Правила языка

- Один термин — одно слово («физлица», «способ доступа»); синонимы не плодить.
- Короткие предложения, активный залог, один тезис — одно предложение.
- Термины и аббревиатуры раскрывать при первом упоминании.
- Формулировки без лозунгов и дублей; запретные слова проекта — в его AGENTS.md.
