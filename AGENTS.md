# AGENTS.md — для ИИ-агентов, разрабатывающих этот репозиторий

## Что это за проект

**skill-creator** — мета-навык для ИИ-агентов: создание, проверка и развитие навыков.

Назначение файлов:

- `SKILL.md` — агенту-пользователю: когда применять, как действовать, что получится.
- `README.md` — человеку: зачем навык нужен, как установить и настроить.
- `AGENTS.md` — агенту-разработчику: архитектура, контракты вывода, правила разработки.
- `references/*.md` — методики и конвенции, на которые ссылается SKILL.md.

## Стандарты и источники

Формат навыка — стандарт Agent Skills. При расхождениях источник истины —
внешние стандарты:

- [Спецификация навыков](https://agentskills.io/specification)

## Архитектура

```
scripts/create.php   — создание каркаса
scripts/hash.php     — подсчёт hash навыка: sha256 с солью «hash: package» (references/package.md)
assets/*.template.*  — шаблоны (плейсхолдеры {{…}})
tests/               — тесты зеркально исходникам: scripts/, docs/; run.php — раннер; lib.php — помощники
references/          — методики и конвенции, на которые ссылается SKILL.md
```

**Контракт вывода `create.php`** (stdout, машиночитаемый, не ломать):
- `ok, files[], placeholders_left`.
- ошибки — в stderr.

## Правила разработки

- Шаблоны и правила меняются вместе.
- Каркас после заполнения плейсхолдеров проходит `php -l` и свои `tests/run.php`.
- Офлайн-тесты и `php -l` — до коммита.
- Тесты каркаса покрывают оба контекста запуска: из каталога навыка и по абсолютному пути из чужого каталога.
- Прямые коммиты в main ветку запрещены, доставка изменений в main только через подтвержденный пользователем PR.

## Правила тестов

- Один тестовый файл — на один тестируемый, зеркально пути: `scripts/hash.php` →
  `tests/scripts/hash.php`. `tests/run.php` — раннер: список файлов, запуск,
  сводный код выхода.
- Тест — обычный PHP-скрипт: fixture → вызов скрипта → `check($cond, 'label')`.
  Общие помощники — в `tests/lib.php`.
- Вызов скрипта из теста: `exec('php ' . escapeshellarg(...), $o, $rc)`, stdout —
  json_decode. Пути всегда через escapeshellarg.
- Проверяй три точки: код выхода, поля stdout, эффект на файловой системе.
- Негативные кейсы равноправны: дурной вход — код 1 и «ничего не создано».
- Fixture — в системном temp с getmypid(); после запуска тестов убирать; сеть не трогать.
- Значения-форматы проверяй формой (64 hex у hash), не конкретным значением —
  оно меняется с содержимым.
- Каркас до заполнения плейсхолдеров должен падать в тестах ровно на
  плейсхолдерах — не на другом.

## Правила языка

- Одно понятие — один термин; синонимы запрещены.
- Используй точные профессиональные термины из предметной области.
- Формулировки однозначные, без двойного толкования и оценочных слов.
- Пиши короткими предложениями без пропуска объектов действия.
- Используй активный залог по схеме: «одно действие (или тезис) — одно предложение».
- Расшифровывай узкие термины и аббревиатуры при первом упоминании.
- Убирай вводную «воду», общие призывы и повторы.
