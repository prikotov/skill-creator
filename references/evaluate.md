# Evaluate — методология оценки навыка AI-агента

## 1. Назначение

Evaluate — процесс систематической оценки качества навыка, формализованного в SKILL.md и реализуемого LLM-агентом.

Цель Evaluate — определить:

- способен ли агент применять описанную методику;
- достигает ли он ожидаемого результата;
- насколько качественно выполняет работу;
- насколько устойчиво применяет методику в разных условиях;
- какие ограничения и проблемы существуют;
- какие улучшения методики обоснованы результатами проверки.

Evaluate оценивает не сам текст SKILL.md, а результат совместной работы модели, инструкций, подключённых инструментов и доступных источников знаний.

**Основной принцип: наличие инструкции не доказывает наличие навыка. Навык подтверждается практическим выполнением деятельности.**

## 2. Объекты оценки

Оценка должна разделять несколько независимых составляющих.

### 2.1. Соответствие методике (Compliance)

Насколько точно агент следует предписанному в SKILL алгоритму работы.

Проверяется:
- соблюдение последовательности операций;
- выполнение обязательных этапов;
- корректное применение условий и ограничений;
- правильный выбор инструментов;
- отсутствие необоснованных отклонений от методики.

Важно: буквальное следование инструкции не всегда является признаком хорошего навыка. Если методика допускает адаптацию, оценивается обоснованность принятых решений.

### 2.2. Качество результата (Quality)

Насколько результат соответствует требованиям задачи.

Проверяется:
- полнота;
- точность;
- корректность;
- соответствие формату;
- отсутствие критических ошибок;
- практическая применимость результата.

Это основной показатель полезности навыка.

### 2.3. Эффективность (Efficiency)

Насколько рационально агент использует ресурсы для достижения результата.

Проверяется:
- количество выполненных операций;
- количество обращений к инструментам;
- расход токенов;
- затраченное время;
- количество повторных попыток;
- объём лишних действий.

Эффективность оценивается только с учётом качества. Уменьшение количества операций не является улучшением, если при этом ухудшается результат.

### 2.4. Устойчивость (Robustness)

Насколько стабильно агент применяет методику при изменении исходных условий.

Проверяется:
- работа с разными входными данными;
- работа с неполными или противоречивыми данными;
- обработка нестандартных ситуаций;
- поведение при ошибках инструментов;
- способность распознавать ситуации, выходящие за пределы применимости SKILL.

### 2.5. Самостоятельность (Autonomy)

Насколько агент способен самостоятельно принимать решения в рамках методики.

Проверяется:
- необходимость дополнительных подсказок;
- способность выбирать подходящий вариант действий;
- способность обнаруживать проблемы;
- способность корректно запрашивать недостающую информацию;
- способность определять ситуации, в которых продолжение работы невозможно или небезопасно.

Самостоятельность не означает отсутствие контроля. Важна способность правильно определять границы собственных возможностей.

## 3. Подготовка к оценке

До начала Evaluate необходимо определить критерии успешности навыка.

### 3.1. Определение ожидаемого результата

Для каждого SKILL необходимо установить:

- назначение;
- класс решаемых задач;
- ожидаемый результат;
- обязательные требования;
- допустимые отклонения;
- критические ошибки;
- ограничения применимости.

### 3.2. Подготовка тестового набора

Необходимо сформировать набор задач, представляющих разные условия применения навыка.

Рекомендуемые категории:

| Категория | Назначение |
|---|---|
| Typical | Типовые задачи |
| Simple | Простые задачи для проверки базовой работоспособности |
| Complex | Сложные задачи с несколькими этапами |
| Edge cases | Пограничные и нестандартные ситуации |
| Negative | Задачи, в которых применение SKILL неуместно |
| Recovery | Задачи с ошибками, сбоями или неполными данными |

Тестовый набор должен содержать не только задачи, на которых создавался SKILL, но и новые примеры, не использовавшиеся при его разработке.

Это позволяет обнаруживать переобучение методики на конкретные примеры.

### 3.3. Эталонные результаты

По возможности для тестовых задач необходимо подготовить эталонные результаты или критерии их независимой проверки.

Не все задачи имеют единственное правильное решение. В таких случаях используются рубрики оценки, набор обязательных условий и экспертная проверка.

## 4. Проведение оценки

Evaluate выполняется по единому протоколу.

### Этап 1. Фиксация условий

Перед тестированием необходимо зафиксировать:

- версию SKILL.md;
- используемую модель и её версию;
- доступные инструменты;
- системные инструкции;
- входные данные;
- параметры выполнения.

Это необходимо для воспроизводимости результатов.

### Этап 2. Выполнение тестовых задач

Агент получает тестовые задачи и выполняет их с использованием проверяемого SKILL.

В ходе выполнения необходимо сохранять:
- входные данные;
- последовательность действий;
- обращения к инструментам;
- промежуточные результаты;
- итоговый результат;
- ошибки и повторные попытки.

### Этап 3. Оценка результатов

Каждый результат проверяется по заранее определённым критериям.

Оценка должна по возможности выполняться независимо от агента, который создал или изменял SKILL.

Предпочтительные способы проверки:

1. Автоматические тесты и детерминированные проверки.
2. Сравнение с эталонными результатами.
3. Проверка по формализованной рубрике.
4. Экспертная оценка.
5. Независимая модель-оценщик (LLM-as-a-Judge).

Для LLM-as-a-Judge необходимо предусмотреть контроль систематических ошибок оценщика и периодическую сверку с человеческой оценкой.

### Этап 4. Повторные испытания

Для задач, результат которых зависит от стохастического поведения модели, желательно проводить несколько независимых запусков.

Это позволяет оценить не только лучший результат, но и воспроизводимость качества.

### Этап 5. Анализ отклонений

Необходимо установить:
- какие требования не выполнены;
- какие ошибки повторяются;
- какие этапы методики вызывают затруднения;
- какие действия оказались избыточными;
- какие ситуации не предусмотрены инструкцией;
- какие проблемы связаны с моделью, инструментами или внешними данными, а не с SKILL.

Последний пункт особенно важен: не всякая ошибка агента требует изменения SKILL.md.

## 5. Система оценки

Для каждого SKILL рекомендуется использовать отдельные показатели по пяти измерениям:

| Показатель | Что измеряет |
|---|---|
| Compliance | Соблюдение методики |
| Quality | Качество результата |
| Efficiency | Эффективность выполнения |
| Robustness | Устойчивость |
| Autonomy | Самостоятельность |

Каждое измерение может оцениваться по шкале от 0 до 5.

- 0 — критерий полностью не выполнен;
- 1 — критические проблемы;
- 2 — существенные недостатки;
- 3 — приемлемое выполнение;
- 4 — хорошее выполнение;
- 5 — отличное выполнение.

Оценка должна сопровождаться доказательствами: конкретными результатами, наблюдениями и примерами.

Не рекомендуется сводить все измерения к одному числу без учёта их значимости. Для некоторых SKILL качество результата является обязательным условием, которое не может компенсироваться высокой эффективностью.

Критические ошибки должны иметь статус блокирующих независимо от итогового среднего балла.

## 6. Результат Evaluate

По завершении оценки формируется отчёт, содержащий:

1. Идентификатор и версию SKILL.
2. Условия тестирования.
3. Описание тестового набора.
4. Результаты по каждому измерению.
5. Выявленные ошибки и ограничения.
6. Примеры успешного и неуспешного выполнения.
7. Сравнение с предыдущими результатами, если оно доступно.
8. Рекомендации по дальнейшему развитию навыка.

Результат оценки должен относиться к одной из категорий:

- **Failed** — навык не обеспечивает минимально приемлемого результата.
- **Needs Improvement** — навык работает, но имеет существенные недостатки.
- **Accepted** — навык соответствует установленным требованиям.
- **Mature** — навык демонстрирует устойчивое качество на разнообразных задачах.

Статус Mature требует более широкого подтверждения, чем успешное прохождение нескольких типовых тестов.

## 7. Связь Evaluate с Evolve

Evaluate и Evolve должны быть разделены функционально.

Evaluate отвечает на вопросы:
- Что получилось?
- Насколько хорошо получилось?
- Где возникли проблемы?
- Какие ограничения обнаружены?
- Есть ли основания считать навык улучшенным?

Evolve отвечает на вопросы:
- Что следует изменить?
- Почему это изменение должно помочь?
- Как именно изменить SKILL.md?
- Как проверить эффективность изменения?

Результаты Evaluate передаются в Evolve в качестве фактической основы для совершенствования методики.

После изменения SKILL необходимо повторить Evaluate, используя тот же тестовый набор и, по возможности, дополнительные независимые задачи.

Это позволяет сравнивать версии SKILL на одинаковых условиях.

## 8. Принципы достоверной оценки

1. **Разделение разработки и проверки.** Агент не должен быть единственным оценщиком собственного результата.
2. **Воспроизводимость.** Условия и тестовые данные должны фиксироваться.
3. **Независимость тестов.** Необходимо проверять работу на новых задачах, а не только на примерах разработки.
4. **Оценка результата.** Соблюдение инструкций не заменяет проверку качества результата.
5. **Контроль регрессий.** Улучшение одних сценариев не должно незаметно ухудшать другие.
6. **Учёт ограничений среды.** Необходимо отличать недостатки SKILL от ограничений модели, инструментов и доступных данных.
7. **Доказательность.** Любая оценка должна иметь наблюдаемое обоснование.

## 9. Главный принцип

Evaluate — это механизм объективной обратной связи в жизненном цикле навыка.

Он не должен подтверждать, что агент хорошо выполнил инструкцию. Он должен устанавливать, насколько хорошо агент научился решать задачу с использованием данной методики.

**SKILL считается сформированным не тогда, когда написана инструкция, а тогда, когда её применение обеспечивает подтверждённое качество результата.**

Evaluate превращает процесс совершенствования SKILL из субъективного редактирования инструкций в итерационный процесс, основанный на измеримых результатах практической деятельности.
