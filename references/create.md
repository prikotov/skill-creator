# Методология создания SKILL: триада «Знание — Умение — Навык»

## 1. Концептуальная модель

При проектировании SKILL следует опираться на триаду «Знание — Умение — Навык» (ЗУН), адаптированную к архитектуре LLM-агентов.

Эта модель разделяет три составляющие интеллектуальной деятельности:

- **Знание (Knowledge)** — информация, факты, закономерности, концепции и модели предметной области, которыми располагает LLM.
- **Умение (Ability)** — способность LLM применять имеющиеся знания, рассуждать, выполнять инструкции, использовать инструменты и решать задачи.
- **Навык (Skill)** — закреплённый способ применения знаний и умений для выполнения определённого класса задач.

В контексте AI-агентов эти понятия имеют следующие соответствия:

| Компонент | Реализация в AI-агенте |
|---|---|
| Знание | Обученные параметры LLM, контекст, подключённые источники знаний |
| Умение | Базовые способности LLM: рассуждение, следование инструкциям, работа с инструментами |
| Навык | Формализованная методика деятельности, представленная в SKILL.md |

**SKILL.md — это внешний, изменяемый носитель навыка**, описывающий способ применения знаний и умений модели для достижения определённого результата.

Сам файл не является способностью модели. Способность реализовать описанный в нём навык возникает при совместной работе LLM и инструкций SKILL.

## 2. Принцип разделения ответственности

При создании SKILL необходимо соблюдать границу между знаниями модели и методикой её деятельности.

Не следует без необходимости дублировать в SKILL общеизвестные знания, которыми располагает базовая LLM.

Вместо этого необходимо описывать:

- какую задачу предстоит решать;
- какой результат требуется получить;
- какую методологию применять;
- в какой последовательности выполнять действия;
- какие критерии использовать при принятии решений;
- как проверять корректность результата;
- как поступать в нестандартных ситуациях;
- какие ошибки и нежелательные действия необходимо предотвращать.

SKILL должен отвечать преимущественно на вопрос **«Как выполнять работу?»**, а не на вопрос «Что необходимо знать о предметной области?».

Если для выполнения задачи нужны специализированные знания, их следует подключать как отдельные источники: документацию, справочные материалы, базы знаний, примеры и другие ресурсы.

## 3. Методология формирования навыка

Создание SKILL следует рассматривать как процесс формализации эффективного способа деятельности.

Исходная методика может быть разработана человеком, получена из существующей документации или сформирована самой LLM на основе анализа задачи.

Рекомендуемый цикл:

1. **Определение задачи.** Установить класс задач, назначение SKILL и ожидаемый результат.
2. **Формирование методики.** Определить последовательность действий, правила принятия решений и критерии качества.
3. **Формализация.** Перенести методику в инструкции SKILL.md.
4. **Практическое применение.** Выполнить реальные задачи с использованием SKILL.
5. **Оценка результата.** Проверить качество, устойчивость и эффективность выполнения.
6. **Рефлексия.** Выявить ошибки, повторяющиеся затруднения и возможности оптимизации.
7. **Совершенствование.** Внести обоснованные изменения в SKILL.md.
8. **Повторная проверка.** Убедиться, что новая версия действительно лучше предыдущей.

Таким образом, SKILL не обязательно должен оставаться статичным документом. Он может эволюционировать вместе с накоплением опыта агента.

## 4. Аналогия с формированием навыков у человека

В педагогической модели ЗУН приобретение навыка предполагает переход от осознанного выполнения действий к их автоматизации.

Например, человек сначала изучает правила управления автомобилем (знания), затем учится управлять автомобилем, сознательно контролируя каждое действие (умение), а после многократной практики выполняет многие операции автоматически (навык).

Для AI-агента можно построить функционально аналогичный механизм:

| Человек | AI-агент |
|---|---|
| Знания | Обученная LLM |
| Осознанное выполнение | Выполнение инструкций SKILL |
| Практика | Повторное выполнение задач |
| Анализ собственного опыта | Рефлексия агента |
| Закрепление навыка | Изменение и оптимизация SKILL.md |
| Автоматизированное выполнение | Использование усовершенствованного SKILL |

Важное отличие: у LLM не обязательно изменяются веса модели. Закрепление опыта происходит через изменение внешнего артефакта — SKILL.md.

Это функциональная аналогия с человеческой нейропластичностью, а не утверждение об идентичности механизмов обучения.

## 5. Принципы проектирования SKILL

### 5.1. Ориентация на результат

SKILL должен описывать не просто набор действий, а способ достижения проверяемого результата.

### 5.2. Минимальная достаточность

Инструкции должны содержать только необходимые правила, процедуры, критерии и ограничения.

Избыточные инструкции увеличивают контекст и могут затруднять выполнение задачи.

### 5.3. Разделение методики и справочных знаний

Методика выполнения задачи должна быть отделена от предметных знаний, используемых в процессе работы.

### 5.4. Явные критерии качества

SKILL должен по возможности содержать критерии оценки результата. Без них агенту сложно определить, насколько успешно он выполнил задачу и какие изменения действительно полезны.

### 5.5. Адаптивность

Не следует заранее описывать все возможные ситуации. Нужно задавать принципы принятия решений, позволяющие агенту адаптировать методику к конкретным условиям.

### 5.6. Проверяемость изменений

Любое совершенствование SKILL должно иметь основание: выявленную проблему, проверенную гипотезу или подтверждённое улучшение.

Накопление изменений само по себе не означает повышения качества навыка.

## 6. Самосовершенствование SKILL

Перспективная архитектура предполагает возможность самостоятельного совершенствования SKILL агентом.

Агент может:

- анализировать собственные результаты;
- выявлять повторяющиеся ошибки;
- находить неэффективные операции;
- предлагать улучшения методики;
- обновлять инструкции;
- проверять обновлённую версию на контрольных задачах.

При этом желательно сохранять историю версий, использовать контрольные примеры и предусматривать возможность отката.

Цель — не бесконечное увеличение инструкций, а постепенное сокращение лишних действий при сохранении или повышении качества результата.

## 7. Главный принцип

**Знания определяют, что модель знает. Умения определяют, что она способна делать. Навыки определяют, как она применяет свои знания и умения для решения задач.**

SKILL Creator должен создавать не энциклопедии знаний и не наборы случайных инструкций, а формализованные методики деятельности, которые можно применять, проверять, совершенствовать и передавать между совместимыми агентами.

SKILL — это не просто инструкция для LLM. Это внешний, версионируемый и потенциально саморазвивающийся носитель методики выполнения деятельности.
