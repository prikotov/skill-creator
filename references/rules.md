# Источники стандарта и что из них взято

Стандарт — синтез трёх источников. Когда правила расходятся — решает
практика наших скиллов (web-research-fallback, moex-site-core, cbr-core).

## 1. `TInvestSkills/docs/SKILL-CREATION.md` — инструкция по созданию SKILL

Взято целиком, это костяк:

- Структура папки: `SKILL.md` (обязателен), `scripts/`, `references/`, `assets/`.
- Frontmatter: `name` kebab-case, `description` до 1024 символов, без XML-тегов.
- Тело: Когда использовать → Как использовать (шаги: команда, опции,
  примеры, результат шага) → Результат (файл/поля).
- Таблица опций в 4 колонки: опция / описание / значения / по умолчанию.

Дополнено нашей практикой: раздел «Правила агента» (запреты, границы,
порядок действий в спорных случаях) — его не было в исходной инструкции.

## 2. Anthropic-тред о внутреннем опыте написания Skills (`skill-creation-2.md`)

Взято:

- **description = «когда использовать»**, не summary. Модель выбирает скилл
  по description.
- **Не пишите очевидного**: только то, что выводит модель из стандартного
  поведения — gotchas, внутренние правила, запреты.
- **Gotchas — обязательная часть**: собирать ошибки модели формулировками
  вида «Таблица X — append-only», «Поле A в сервисе B = поле C в шлюзе».
- **Progressive disclosure**: `references/api.md`, `assets/`, `scripts/` —
  модель читает нужный файл в нужный момент, а не тащит всё в SKILL.md.
- **Скрипты > генерация кода**: готовые helper'ы, модель компонует.
- **Данные — в стабильной папке**, не в каталоге скилла (при обновлении
  скилла не теряются).

Не взято:

- Структура `README.md + description.txt` вместо SKILL.md — у нас принят
  формат SKILL.md с frontmatter (инструкция 1 и все наши скиллы).
- «Не загоняйте в рельсы» понято как: правила и информация вместо
  пошаговых «всегда делай так», но таблицы опций и контракты вывода —
  обязательны: без них агент угадывает.

## 3. Наши скиллы — что добавилось на практике

- **Разделение адресатов**: SKILL.md — агенту-пользователю, README —
  человеку, AGENTS.md — агенту, разрабатывающему репо. Дублирование между
  ними — ошибка.
- **Что не в SKILL.md**: требования к бинарнику, устройство клиента, порядок
  способов, ключи — это README; справочные факты о среде — `references/`.
- **Терминологическая дисциплина**: один термин — одно слово; запретные
  слова фиксируются в AGENTS.md проекта.
- **stdout = JSON-контракт, stderr = прогресс**, код выхода 0/1 — во всех
  скриптах, чтобы агент парсил результат, а не читал простыню.
- **PHP 8.4+, ext-curl, без composer** — стек владельца; скиллы на Python
  мигрируют (moex-site-core переведён 2026-11-25).
- **Ловушки переезда на PHP** (из moex-site-core): PDO автокоммитит на
  строку — массовая запись только в транзакции; `WHERE LOWER(col)` без
  индекса — полный скан на каждый апсерт.
- **Оформление репо** (образец `prikotov/knowledge-extraction`): LICENSE
  MIT, AGENTS.md, `tests/run.php` + CI (`php -l` + тесты), README с разделами
  Безопасность/Конфиг, Лицензия; description на GitHub начинается со
  «Skill для AI-агентов», branch protection `main`.
- **Пример запроса агенту — только реальный**, дословно из истории сессии:
  выдуманные сценарии выглядят правдоподобно, но не учат ничему.

## Чеклист «SKILL.md или README?»

| Факт | Куда |
|------|------|
| Когда применять скилл | SKILL.md (description + раздел) |
| Опции скрипта, значения по умолчанию | SKILL.md |
| Поля JSON-результата | SKILL.md |
| Запреты и границы для агента | SKILL.md, «Правила агента» |
| Как установить скилл | README |
| Из чего состоит клиент, порядок способов | README, «Как устроено» |
| Ключи и конфиг | README, «Конфиг и секреты» |
| Поведение сайтов/API, ловушки, отрицательные результаты | `references/` |
| Правила разработки репо, контракты вывода | AGENTS.md |
| Тестовые запросы и пробы владельца | никуда (не пишутся) |
